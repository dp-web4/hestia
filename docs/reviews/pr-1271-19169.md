absent baseline. Other directory-open errors and directory-entry errors propagate
before checkpoint acceptance, cache quarantine, or replay. `load` now propagates
errors checking either the disposable cache path or the baseline path instead of
treating an uncheckable path as a new entity.

both fail while the baseline directory is inaccessible; restoring permissions
allows the seven-action baseline plus the retained row to reconstruct all eight
actions. The changed lost-cache-write fixture and the previous charge-loss,
double-charge, partial-checkpoint, cache-ahead, and chain-reconstruction cases pass.

Added `review_19169_baseline_file_blocks_replay_without_publishing` as a second
error-path regression. It temporarily replaces the baseline directory with a
regular file after removing the disposable cache. Recovery, read, and replay all
return errors; dropping the store publishes no cache and leaves the checkpoint
byte-for-byte unchanged. Restoring the directory allows replay, and a further
restart verifies the resulting checkpoint and all eight actions. This test
requires no permission-denial fixture.

The manifest and durable epoch address the two recovery cases in review 19153.

unacknowledged chain rows did not survive recovery.

## P1: validate cache state against the recovered chain, not just its manifest

`TrustStore::recover` (`core/src/storage/trust.rs:268-280`) accepts a checkpoint
when every listed file is at least as far as the manifest says. It does not
check either checkpoint or entity positions against the recovered chain.
`chain_len` is used to choose a legacy epoch, not to reject future cache state.

The cache writer has no dependency on the chain durability frontier. A cache
batch can finish while chain fsync is held. Following a system crash, those
files may survive while the unacknowledged WAL suffix does not. The manifest
and entity files agree with each other, but not with the source of truth.
Recovery retains their trust values and can begin replay beyond the chain end.

This is a projection consistency bug even though the missing request was never
acknowledged: once startup chooses the recovered chain as authority, it must
not expose effects absent from that chain. Per-entity `through` makes forward
replay idempotent; it cannot undo changes from a lost suffix.

The test-only reproduction
`review_19161_cache_ahead_of_recovered_chain_keeps_an_unwitnessed_charge` uses
an isolated temporary home:

1. Durably witness a first deny, close the store, and save the clean chain image.
2. Reopen, hold chain fsync, witness a second deny without acknowledging
   durability, and flush the trust cache. Assert that committed chain length
   advanced while the durable frontier did not.
3. Close, preserve all cache files, and restore the saved chain prefix. This
   constructs a recovery image; it is not a physical power-failure experiment.
4. Reopen. The second decision is absent from the chain, but the trust action
   count remains **2**, rather than the recovered chain's **1**.

Repair either the ordering or recovery contract: publish cache versions only
after their source rows are durable, or validate and rebuild versions that do
not belong to the recovered prefix. Merely clamping the global replay start is
insufficient because `apply_at` skips rows at or below each entity's retained
`through`. A recovery repair must also preserve any pre-epoch legacy baseline.

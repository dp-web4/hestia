## P1: a loop can assign IFS without invalidating unquoted literals

```sh
S=/tmp:/etc; for IFS in :; do cat $S/hostname; done
```

The helper, core, and all four adapters ALLOW this command. Bash passes
`/tmp` and `/etc/hostname` as separate arguments. The latter is outside the
test policy's allowed roots, but the classifier judges the combined temporary
pathname and never requests scope for the second argument.

In the reconstructed `plugins/_shared/hestia_gate_core.py`,
`_outside_candidates` line 1896 detects only words matching `IFS\+?=`.
A `for IFS in ...` binding has no equals sign. `_literal_names` recognizes
`for` but bans only the loop variable itself; it leaves S bindable. Therefore
line 1937 stores S with `needs_quote=False`, and `_word_value` resolves its
unquoted use as one pathname. The corresponding hooks-gt copy needs the same
repair.

Treat loop binding of IFS as invalidating the splitting assumption for every
literal, or conservatively require quoted use whenever that assumption cannot
be proved. Keep the double-quoted control allowed: it produces the single
argument `/tmp:/etc/hostname`.

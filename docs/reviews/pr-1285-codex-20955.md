## P2 — Handle a failed re-bind as a post-publication failure

At `tools/release_publish.py:160`, the new recovery PATCH can raise
`RuntimeError`. This reaches the existing outer handler at lines 199–202,
which reports that the release "is left as a DRAFT and was NOT published."
Publication has already succeeded at this point. If the first PATCH left the
placeholder and the recovery PATCH fails, the release is public and untagged,
exactly the state this change needs to make unmistakable. The exception also
skips the new manual repair command.

Reproduced using the PR's subprocess mocked-gh harness, with two narrow changes
to its mock: discard `tag_name` only on the publishing PATCH, then return HTTP
500 on the re-bind. Result: exit 1, `draft=false`,
`tag_name=untagged-d4c9c308d31f0db84ef6`, followed by:

```text
::warning::v0.3.0: published release 4242 is not reachable by its tag; re-binding tag_name once
::error::gh api -X PATCH ... failed (1): HTTP 500: mock rebind failure
::error::v0.3.0 is left as a DRAFT and was NOT published.
```

The nonzero exit is correct; the asserted remote state is not. Catch recovery
errors within the post-publication phase and report that publication succeeded
but tag binding could not be verified/repaired, retaining the release ID and
manual repair command. Cover a failed re-bind, in addition to an ignored
successful PATCH. Do not infer a known draft state from a transport error.

Reproduction: `python3 docs/reviews/pr-1285-codex-20955-repro.py`.
It also proves that dropping the first tag binding but accepting the re-bind
recovers successfully. It exits 1 when the false draft diagnostic reproduces.
Both scenarios use fake releases and a fake `gh`; no release is changed.

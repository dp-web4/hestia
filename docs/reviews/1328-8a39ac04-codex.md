## P1: a later `-f` turns an already-exempted positional into a program file

Locations in the reconstructed `plugins/_shared/hestia_gate_core.py`:
`_CMD_SPECS["jq"]`, the `program_file_opts` handling in `_outside_candidates`,
and the `pattern_first` branch at lines 2458–2461. The hooks-gt copy has the same
behavior.

jq permits options after its program operand. Its `-f`/`--from-file` option
sets the mode for that operand regardless of their ordering. The gate instead
exempts the first positional as data immediately, before processing a later
file-mode option; it never revisits that exemption.

Fixture: W is the synthetic workspace, only W/granted has a recursive path
grant, cwd is W/granted, and sibling O is outside W and ungranted. O/program.jq
contains `"outside-program-marker"` followed by a newline. All fixture paths
are outside the gate's unconditional temporary roots.

```text
jq -n O/program.jq -f
jq -n O/program.jq --from-file
jq -n O/program.jq -rf

base, each:    (False, <offending file>, O/program.jq)
patched, each: (True, None, None)
```

Actual jq 1.7.1 exits zero and prints the marker for all three commands. The
first two print a JSON string; `-rf` prints the raw string.

Determine file mode for the entire simple command before granting the
positional-program exception, or retain and reclassify the earlier operand.
Add outside-scope controls with file-mode options both before and after the
program, including a short-option cluster. Model jq's actual option semantics:
`-f` selects how the program operand is interpreted, rather than necessarily
consuming the immediately following token as its operand.

## P1: two-value file options can move the program exemption onto the file

Locations: the new jq specification at lines 1583–1585, and the same
`pattern_first` branch. The comment above the spec claims that a two-value
option can move the exception only onto its NAME. That is false when NAME
looks like an option.

```text
jq -n --rawfile --name O/data.json '$ARGS.named["--name"]'
jq -n --slurpfile --name O/data.json '$ARGS.named["--name"]'

base, each:    (False, <offending file>, O/data.json)
patched, each: (True, None, None)
```

For this probe O/data.json contains `"outside-data-marker"` and a newline.
Actual jq 1.7.1 accepts `--name` as the option's NAME, reads O/data.json, and
exits zero. `--rawfile` prints its contents as a string; `--slurpfile` prints
an array containing the parsed marker.

The gate has no arity model for these options. It treats `--name` as another
flag, making the file the first positional and exempting it as the jq program.
Consume NAME and FILE explicitly for `--rawfile` and `--slurpfile`, without
reinterpreting NAME as an option. Add independent controls for ordinary and
option-shaped names, and cover the arity interactions of `--arg`/`--argjson`
before relying on the positional-program exception.

The upstream [jq 1.7.1 argument parser](https://github.com/jqlang/jq/blob/jq-1.7.1/src/main.c)
corroborates both executions: it records the first non-option as `program`,
sets `FROM_FILE` separately, and consumes two arguments for each file-binding
option without validating NAME as an identifier. These are observations of
the pinned release, not assumptions about a current jq installation.

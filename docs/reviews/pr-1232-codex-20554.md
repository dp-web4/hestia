## P1: whitespace is not the complete field-splitting condition

```sh
IFS=:; S=/tmp:/etc; cat $S/hostname
```

This ALLOWs at every layer. Bash actually passes `/tmp` and `/etc/hostname`
as two separate arguments. `_outside_candidates` records `needs_quote` by
testing only space, tab, and newline in the literal. `_literal_names` excludes
IFS itself from the bindable set, but assigning IFS does not invalidate S.
Consequently `_word_value` substitutes one `/tmp:/etc/hostname` pathname and
never judges the second argument.

The quoted control `cat "$S/hostname"` really is one pathname and correctly
allows. Preserve this distinction. Conservatively disqualifying unquoted
bindings when IFS is assigned fixes this demonstrated command; inherited,
unexported shell state also means the default IFS must not simply be assumed
without a stated execution contract. Requiring quoted use for this exception
avoids modelling arbitrary splitting.

Constructs: `plugins/_shared/hestia_gate_core.py::_outside_candidates`
(`found.known[name_] = (val_, any(c in val_ for c in " \\t\\n"), idx)`),
`_literal_names`, `_word_value`; corresponding hooks-gt copy.

## P1: source text can forge the double-quote marker

The lexer introduces `_DQ_REF = "\\x04"`, and `_word_value` trusts any
occurrence immediately before a reference as evidence of double quoting.
There is no distinction between the inserted marker and the same character
already present in the input command.

These Python strings represent the exact classifier inputs. `\x04` denotes
one literal EOT character, not four shell characters or an ANSI-C expansion:

```python
'S="/tmp/x /etc"; cat \x04$S/hostname'
'S="/tmp/x /etc"; cat \'\x04\'$S/hostname'
```

Both ALLOW at all six paths. Bash treats the EOT as ordinary word data; the
reference is unquoted in both cases. It passes an EOT-prefixed `/tmp/x` first,
then `/etc/hostname`. The parser accepts the forged quote evidence and strips
the marker, judging only the combined temporary pathname.

Keep quote provenance out of user-controlled strings, or conservatively
reject marker collisions before inserting internal markers. Apply that
discipline to every internal sentinel, not just this newly added byte.

Constructs: `_DQ_REF`, `_tokenize`, `_word_value`'s `value[a - 1]` check and
unconditional marker replacement.

## PR 1232 needs three scope fixes

All findings below use synthetic, nonexistent target paths and command strings passed as data to the classifier. The represented shell commands were never executed. Direct access to the same ungranted target was refused. Equivalent forms were allowed by both `command_scope_reach` and core evaluation. Representative cases from all three classes were also allowed by the full `decide()` orchestrator using the repository's disposable policy stub, with `evidence_committed=True`.

### P1 Interpreter invocation variants lose executable content

The `_outside_candidates` shell-code path recognizes the standalone command-string option but misses combined shell option forms. An additional shell builtin wrapper around an evaluation primitive is also missed. These are native shell invocation forms, not custom wrappers. The gate consequently treats executable text as an ordinary argument rather than inspecting it or flagging its reach as unknown.

Fix option and wrapper recognition, or return the existing unenumerated-target request for unsupported interpreter forms. Add equivalence tests against the directly refused command and the already-recognized standalone option form. Source: the interpreter dispatch and pending-option branches in [the held patch](https://github.com/dp-web4/hestia/blob/4d77692f477e9796fc0327f1813de04853843de1/held/c36101e4fbe0e459c9de2584db08c4c7b841d29b6482b8b1293fe23855c868e3.patch#L951).

### P1 ANSI C quoting changes path classification

The tokenizer handles ordinary quoted words but not ANSI-C quoted words. It retains the dollar prefix as though it were literal path content. Even without any escape decoding, a quoted absolute target can therefore evade the absolute-target check.

Recognize this quoting form conservatively. If decoding is outside the intentionally narrow grammar, classify the target as unenumerated rather than accepting a differently spelled path. Source: [`_tokenize`](https://github.com/dp-web4/hestia/blob/4d77692f477e9796fc0327f1813de04853843de1/held/c36101e4fbe0e459c9de2584db08c4c7b841d29b6482b8b1293fe23855c868e3.patch#L452).

### P1 Shell input is treated as inert data

Shell code supplied through a here-string is skipped as redirection data. Feeding the same code through a pipeline, or an explicit descriptor used as a shell script source, also passes the classifier. The false allow for the here-string form was independently confirmed through the full orchestrator; the other two were confirmed at classifier/core level.

Recognize shell execution from stdin or descriptors as executable or unknown reach. No general output simulation is necessary: unsupported code-input forms should use the existing once-only escalation path. Preserve negative controls for genuinely inert data consumers. Source: [`_outside_candidates` redirection handling](https://github.com/dp-web4/hestia/blob/4d77692f477e9796fc0327f1813de04853843de1/held/c36101e4fbe0e459c9de2584db08c4c7b841d29b6482b8b1293fe23855c868e3.patch#L901).

These findings are gaps in the proposed ordinary-shell coverage, not a claim that the patch creates every bypass anew. They do not justify restoring expansion-output or variable-value simulation. Unknown execution reach should become an explicit request, not an allow.

## PR 1232 evidence and operating cost

The narrowed shell battery passed all 671 cases. Patched source and published copies matched, including manifest content addresses. The full contract suite passed, including 29 parity cases across four shims; its real-daemon arm was explicitly skipped. The suite's printed count of 21 includes that skipped arm. Those green results do not cover the independent failure classes above. Full-orchestrator probes used a policy stub; they are not a real-daemon approval-consumption test for 1232.

An initial contract run from a checkout directly under the temporary root produced four fixture failures: the suite inferred that whole root as its workspace and classified ordinary temporary paths as ungranted workspace children. A fresh nested checkout corrected that fixture layout and passed without changing production source. This distinction matters when reproducing the suite.

The author's [measurement tables](https://github.com/dp-web4/hestia/blob/4d77692f477e9796fc0327f1813de04853843de1/held/measure-1232/tables.md) report 11,415 additional refusals among 53,590 recorded commands with proposed grants: 21.3%, including 9,727 once-only requests. These are author measurements, not an independently replayed corpus in this review. The separate shape table reports 9,677 requests; reconcile those sweep counts before treating the breakdown as a single frozen dataset.

That operating cost remains a separate operator decision even after the false allows are fixed. The reported alternative literal-assignment rule reduces refusals, but it is not in this narrowed patch and should not be introduced without changing the agreed scope explicitly.

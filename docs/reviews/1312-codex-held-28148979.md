## 1. POSIX character classes are outside the glob check's model

Construct: `_literal_for_body_uncertain`, the `_fnmatch.fnmatchcase(name, word)`
test. Python fnmatch does not implement Bash's POSIX character classes. A body
head such as `c[[:alpha:]]` can expand to a file named `cd`, while the new matcher
does not recognize it as matching the stateful builtin. Quote deletion does not
remove this discrepancy.

Suggested reproduction: reuse the previous review's three-iteration directory
fixture, with `ws/sub/sub` pointing to the fixture's ungranted sibling directory.
Place a file named `cd` in each of those directories. Check:

```bash
for f in secret.txt secret.txt secret.txt; do cat $f; c[[:alpha:]] sub; done
```

For a safe execution oracle, replace `cat $f` with `pwd -P` and inspect the third
printed directory. Compare base and patched `command_scope_reach`, and assert
that the patched `_literal_for_iterations` refuses this body. Also check
`[[:lower:]]d` and `c[[:alnum:]]`.

Recommendation: refuse unsupported glob syntax conservatively. A Python glob
matcher is not sufficient evidence that a Bash command word cannot name a builtin.

## 2. Dot-source exclusion misses shell command positions

Construct: `_LITERAL_FOR_STATEFUL`, the dot-source alternative requiring start
of body or a punctuation separator immediately before optional whitespace and
`.`. Source is also a command after control words or a pipeline negation:

```bash
for f in secret.txt secret.txt secret.txt; do cat $f; ! . ./move; done
for f in secret.txt secret.txt secret.txt; do cat $f; if . ./move; then :; fi; done
```

Let the fixture file `move` contain `cd sub`. The source acts in the current
shell, so its directory change persists. Neither `!` nor `if` matches that
position prefix, and a plain `.` is not sent through the glob-name check because
it has no glob character. The helper therefore appears to accept these bodies.
The ordinary judge may independently refuse one of these forms; that must be
measured before calling this an end-to-end false allow. Use the same `pwd -P`
oracle and before/after comparison as above.

Recommendation: conservatively refuse a standalone source word independent of
its syntactic position, or use a parser that actually identifies command words.

## P1: package-version equality silently replaces newer source builds

`deploy/fleet/install.sh`, `guard_downgrade` (lines 860–863), extracts only the
first numeric triple from the installed version, drops the target's prerelease
suffix, and immediately accepts equality. The CLI actually reports both the
package version and build provenance (`core/src/cli.rs`, `VERSION`). Source
builds ahead of a release retain that release's package version.

Consequently an installed `hestia 0.0.4 (v0.0.4-12-gabc1234)` is silently
replaced by release `v0.0.4`. This remains reachable with no explicit pin when
latest is v0.0.4, or through the API-failure fallback. It removes newer code
without the required downgrade override. The motivating issue #520 explicitly
includes a source-built installation. The same early return also accepts a
stable 0.0.4 to v0.0.4-rc.1 downgrade.

Preserve release/prerelease ordering and available build provenance. If a source
build is ahead of the same release, require the override; if its relationship
to the target cannot be established, report that uncertainty before replacement.
Keep genuine same-release reinstall working.

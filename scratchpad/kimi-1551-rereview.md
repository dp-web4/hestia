This corroborates Codex's three re-review findings. The focused public-API checks below add two shell forms not named there; the health-surface contract issue in item 4 is additional.

1. **[P1] Visible shell consumers still bypass all resource assessment** (`core/src/policy/resources.rs:372-378`, `417-455`; `core/src/policy/engine.rs:163-177`). Wrapper options with separate nonnumeric values are mistaken for the executable, only a standalone `-c` is recognized for shells, backslashes remain in the executable name, and shell negation is not skipped. Consequently the anchored `^cargo…` consumer never matches, so there is no floor check, R6 observation or runner refusal. `bash -lc 'cargo build'` is another source-confirmed example. Parse the actual shell argv forms and exercise them through `matching_resources` and an enforcing gate. A raw-text fallback is not conservative for these anchored patterns when a wrapper or shell prefix precedes the consumer.

2. **[P1] Restart recovery still loses an old open remedy** (`core/src/server/resource_remedy.rs:163-180`). Rehydration reads only the newest 10,000 remedy events. A still-open request whose opening row falls behind that window disappears from the dashboard on restart even though its durable evidence has no later clear. A read error likewise becomes an empty dashboard projection with only a log warning. Rebuild from complete history or persist the open projection, make incomplete recovery visible, and add a restart regression with the opener outside the window.

3. **[P2] Refusal text can assert a dashboard remedy that was never committed** (`core/src/policy/resources.rs:565-569`; `core/src/server/resource_remedy.rs:121-130`). The negotiation is built before `note`; if `resource_remedy_requested` fails to append, the map correctly stays empty but the refusal still says the operator is asked on the dashboard. Report the committed request state or state the remedy without claiming a request exists, and assert the refusal text in the append-failure test.

4. **[P2] A stuck probe is never reported without a later consuming act** (`core/src/server/handler.rs:2050-2083`; `core/src/policy/resource_probes.rs:50-61`). `stuck_probes` and `note_stuck` are called only while finishing a gate call with a nonempty resource assessment. The initial call returns unknown after 400 ms, when the probe is far younger than the 120 s health threshold; if no later consuming act arrives, no timer or dashboard poll checks again and the promised health request never opens. Add a periodic health pass (or an equivalent polled read path) and test time advancing without another gate call.

5. **[P2] The health-remedy contract contradicts both the app type and `on_unknown`** (`core/src/server/resource_remedy.rs:43-44`, `245-252`; `app/src/lib/types.ts:164-179`). The daemon emits `mode: "health"`, but the app declares only `"observe" | "enforce"`. Its operator text also says unread floors “refuse nothing”, which is false for declarations using the newly added `on_unknown: refuse`. Include `health` in the wire type and make the guidance refer to each floor's declared unknown policy.

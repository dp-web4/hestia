## P1: write-out formats can select an ungranted output file

```sh
cd O && curl -q -sS --write-out '%output{fresh.txt}marker' http://h/fresh.txt
```

Main refuses; the held patch returns `(True, None, None)`. The explicit control
`touch O/fresh.txt` is refused with the same grants. Real curl 8.5.0 exits zero
and writes `O/fresh.txt` containing `marker`. The short `-w` and attached
`-w%output{fresh.txt}marker` forms reproduce the same result.

`_CURL_VALUE_LONG` explicitly includes `--write-out`, while the short-option
scan stops at `w` as a value-taking letter. Neither path judges the destination
embedded in the format. The [curl manual's write-out section](https://curl.se/docs/manpage.html#-w)
documents this file selector, introduced in 8.3.0; the real execution establishes
the behavior for the installed version.

Please judge write-out destinations or conservatively withhold the URL exemption
for these forms. Removing only the long allowlist entry leaves both short forms.

## P1: a granted output template is not a grant on its expanded filenames

Additionally grant the exact literal path `O/out#1`:

```sh
cd O && curl -q -sS -o 'out#1' 'http://h/[1-2]'
```

Main refuses; the held patch returns `(True, None, None)`. Explicit writes to
`O/out1` and `O/out2` are both refused. Real curl exits zero, writes the response
marker into both files, and never creates `O/out#1`. The long `--output out#1`
form reproduces this too.

These are quoted URL patterns: the shell does not expand them, but curl does.
The [curl manual's output section](https://curl.se/docs/manpage.html#-o)
documents substitution of URL glob values into numbered output placeholders.
Judging the literal output option's value therefore does not establish the
actual destination. Please enumerate those destinations, or conservatively
withhold the URL exemption when output templates and URL globbing can interact.

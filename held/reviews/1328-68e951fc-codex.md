## P1: option values can falsely establish a safe output mode

In `_url_output_established`, scanning every option-shaped word is conservative when
the result **removes** an exemption. It is unsafe when the result **grants** one:
`named_output = True` and `spider = True` also accept words that another option
consumes as its value.

Let `O` be a fixture directory outside the simulated workspace, with an exact
`path:O` grant, and start in a granted workspace directory. These commands are
refused by base `2d79644f` and allowed by the reconstructed patch:

```sh
cd O && wget -q -U -O- http://h/fresh.txt
cd O && wget -q --user-agent --spider http://h/fresh.txt
```

Neither selects stdout nor spider mode. `-U` / `--user-agent` consumes the next
word as the user-agent string, as documented in the
[GNU Wget manual](https://www.gnu.org/software/wget/manual/html_node/HTTP-Options.html).
The client retains its default download behavior. Against a disposable local HTTP
fixture, GNU Wget 1.21.4 returned zero and wrote `O/fresh.txt` containing
`review marker\n` for **both** invocations. That child has no grant.

Recognize positive output evidence only at actual option positions, honoring
option arity and attached values. If the command's grammar cannot be established,
retain refusal. Add both commands as must-refuse rows, and preserve real
`wget -qO- URL`, `wget --spider URL`, and explicitly granted output destinations
as must-allow controls. Apply the same distinction to other clients' positive
output evidence.

## 12929 — the env-assignment false positive: mechanism verified, with a refinement

Withdrawal reason: the command wrote only under /tmp; it set an HGC_* env var whose VALUE
named the claude hook file; "the out-of-grammar closure rule read that assignment as a
write." (The test `cross_harness_closure_test.py` reads HGC_CLAUDE/HGC_KIMI/HGC_CODEX/HGC_SHARED
overrides — that is the assignment family in question.)

I probed `classify()` from `plugins/_shared/hestia_governance_closure.py` (sha256
33cdc9e7…, byte-identical to the installed `~/.hestia/shared` copy the shims actually run —
verified by hash, not by the asker's `cmp` claim alone):

- **19 assignment shapes** (bare assignment, `export`, assignment + python3/python/pytest/sh/
  unknown head, backtick value, relative value, assignment + cp-to-/tmp, assignment + redirect
  to a literal /tmp file) all classify **read**. An assignment VALUE naming a closure file is
  NOT, by itself, a write.
- **Add any out-of-grammar trigger** — a substitution in a write position (`> "$OUT"`,
  `| tee "$F"`, `cp x "$D/"`), `bash -c`, `eval` — and the same assignment token flips the
  command to **write** via `governance-closure-out-of-grammar` (marker `plugins/*/hooks`).
  The scan is full-vocabulary: a closure path inside a trailing `# comment` triggers it too.

So the withdrawal's causal claim reproduces, with one refinement: the trigger is not the
assignment alone but the assignment token matching during a vocabulary scan that a separate
out-of-grammar construct forced. The claim "false positive" is accurate, and the fail-closed
direction is the module's documented trade (classify() phase-1 comment: broader read-position
semantics, fail closed as write if ANY token is closure vocabulary). Re-running with the
test's in-repo default path resolution (HGC_* unset) was the right remedy.

Live corroborating instance from this wake: staging my unpatched-control mirror with a Bash
`cp` whose destination path contained the substring `plugins/_shared` under /tmp was denied
as `governance-closure-write`. Same vocabulary-anywhere class, on the write side. I adjusted
(driver script keeps closure vocabulary out of the command line; the scratch target is not a
governed file) and disclose it here rather than working around silently.

## P1: URL exemption authorizes creation of an ungranted relative path

Locations: `_network_url`, `url_argument` in `_outside_candidates`, and the
`urls` filtering block in `_command_scope_reach_one`, in both gate-core copies.

The exemption accepts any non-`file` scheme for any command, then drops the
candidate when its first component does not exist at preflight. Nonexistence
does not establish that a word is a network URL: filesystem commands can create
that very component.

Reproduction uses only disposable fixtures. W is a synthetic workspace with a
`granted` subdirectory; O is an existing sibling outside W. Grant `path:W/**`
and **only** `path:O`, with event cwd `W/granted`. Initially `O/http:` is absent.

```sh
cd O && mkdir -p http://newdir
```

Replace O with its absolute fixture path. With identical fixture state, grants,
workspace and cwd:

```text
base:    (False, <offending path>, O/http:/newdir)
patched: (True, None, None)
```

Actual `mkdir -p http://newdir`, executed with cwd O, exits zero and creates
the ordinary directory `O/http:/newdir`. This is a descendant write outside
the exact grant. It is not network access or hypothetical URL interpretation.

An additional classifier probe, before creating `http:`, also separates the
cores:

```sh
cd O && mkdir http: && touch http://newfile
```

The base refuses `O/http:/newfile`; the patch allows it. This second form was
compared in the cores, not executed. It illustrates why checking directory
existence once cannot establish how later words resolve after preceding commands.

Restrict the exemption to command/operand positions known to consume URLs.
Preserve path judgment for filesystem consumers and unknown consumers, even
when the URL-looking first component is absent. Add must-deny controls for
creation under an exact directory grant and for a preceding command creating
the scheme-named directory. Keep the existing network-client must-allow controls.
